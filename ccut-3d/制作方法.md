# 长春工业大学北湖校区东区 · 3D 校园模型制作方法论

> 本文档基于本目录代码（`gen.py` / `data.js` / `campus.js` / `visual-style.js` / `game.js` / `index.html` / `tools/*`）反推整理。
> 适合「vibe coding」场景：你用对话式 AI（Codex 等）生成和迭代，底层是一套「真实地理数据 → 程序化建模 → 浏览器渲染」的管线。

---

## 〇、一句话总结

把**真实地图（OpenStreetMap 矢量 + Esri 卫星底图）**用脚本投影成「以米为单位的平面坐标」，再让 **three.js** 把每栋楼的轮廓「拉高成盒子」，贴上按用途分类的墙面/屋顶材质，最后套一个 **第一人称漫游 + 截图验收 + 单元测试** 的迭代闭环。

---

## 一、人话版：这套东西到底是怎么"捏"出来的

按时间顺序，一共 9 步，前 5 步是"备料"，后 4 步是"建模+打磨"：

1. **取证**：从 OpenStreetMap 导出校园的楼、路、湖、树轮廓（得到 `osm.json`），再从 Esri 卫星图下载一张拼接好的校园正射影像（`mosaic_full.png`）。
2. **换坐标**：把 GPS 经纬度换算成"以校园中心为原点的米"（东北方向 = x / z 轴），这样之后所有东西都用"米"说话，不用再管经纬度。
3. **扒楼**：脚本遍历地图里的每栋建筑，记录它的轮廓点、层数（OSM 里有 `building:levels`）、叫什么名字。楼层 × 一层 3.6m ≈ 楼高。
4. **卫星补刀**：地图上没标、但卫星图上看得见的楼（看台、宿舍塔楼等），用"在卫星预览图上量像素框"的方式手动补进去（`gen.py` 里的 `MAN` 表）。
5. **取屋顶色**：每栋楼在卫星图上"抠"出它屋顶的平均颜色，自动当屋顶色，省得人工配色。
6. **贴地**：把卫星影像切成 4×4 块、压成 base64 直接塞进网页，当作地面——于是你看到的草坪、操场、路面，就是真实卫星照片。
7. **拉盒子**：每栋楼的轮廓 `ExtrudeGeometry`（挤出）成对应高度的立体盒子；按 `kind`（宿舍/教学楼/住宅…）自动选墙面颜色、屋顶样式（宿舍是坡屋顶+两端红砖楼梯间，教学楼是带柱廊的山花立面）。
8. **加戏**：主教学楼用"地标"风格做精致立面；可再叠一个用 Blender 建模、导出 GLB 的"英雄模型"盖在盒子上当高清替身；再加路、湖、树、路灯、昼夜切换。
9. **验收**：用无头浏览器（Playwright + Chrome）自动飞到指定机位截图，肉眼/像素对比；同时跑单元测试守住"地面不穿模、招牌不重叠、按键不乱"这些回归项。

> 你给我的"加研究生宿舍"任务，只动到了第 3~4 步的**数据层**（`data.js`），渲染层一行没改——因为新楼用了和其它宿舍一模一样的参数，three.js 会"自动按老样子画出来"。这就是这套架构最省力的地方。

## 二、思维链条（Thinking Chain / 我的推理路径）

下面这条链是我**加研究生宿舍那次**的真实思考顺序，也是你以后做任何"在地图上加东西"的通式：

```
[目标] 食堂右侧空地 → 研究生宿舍，要和其它宿舍同款
   │
   ├─① 先定位"数据入口在哪"
   │     → 读 index.html：加载顺序 data.js → campus.js
   │     → 结论：所有建筑都来自 CAMPUS_DATA.buildings，改 data.js 即可
   │
   ├─② 搞清楚"宿舍长什么样"
   │     → grep "宿舍"/"dorm"：campus.js 里 kind==='dormitory' 自动走 style='dorm'
   │     → 同款特征：h=22.4（6层）、roof='#878573'、两端深红楼梯间、坡屋顶、米黄墙
   │     → 结论：新楼只要填相同字段，样式零成本复用
   │
   ├─③ 找到食堂和空地的真实坐标
   │     → 解析 data.js：东区食堂 x[24,100] z[-271,-198]
   │     → 读 roads：北 z≈-287、南 z≈-153、西 x≈108 各有一条路，把空地框住
   │     → 结论：空地 ≈ x[110,350] × z[-280,-160]，两排板楼刚好放得下
   │
   ├─④ 对齐既有宿舍的"节奏"（不凭空造参数）
   │     → 西侧宿舍是 3 组 84m×17.6m 板楼、两排错开
   │     → 结论：东侧照抄——两排各 2 栋，间距/退让对齐道路
   │
   ├─⑤ 用脚本批量插数据（不动渲染代码）
   │     → Python 解析 data.js JSON → append 4 栋 + 1 个传送点 → 原样序列化回写
   │     → 备份 data.js.bak-grad
   │
   ├─⑥ 截图验证"真长出来了"
   │     → 复用项目现成的 Playwright 渲染脚本，飞到地面机位 + 高空机位截图
   │     → 肉眼确认：样式一致、没压到路、label 正常
   │
   ├─⑦ 跑单测防回归
   │     → node --test 现有用例全过（16/16）
   │
   └─⑧ 诚实交代"坑"
         → gen.py 重跑会覆盖 data.js；要长期保留得把楼写进 gen.py 的 MAN 表
```

**最没把握的一步**：第③步里"空地真实边界"是靠道路坐标反推的，没有逐栋核对卫星图——如果将来发现某栋楼其实压到了规划路/绿化带，回到第④步微调坐标即可（改 `data.js` 里那几个 x/z 数字）。

## 三、专业版：技术管线与工具清单

### 3.1 技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 渲染 | **three.js**（旧版 r1xx，`THREE.sRGBEncoding` / `CanvasTexture` / `ExtrudeGeometry`）| 纯 WebGL，单文件 `three.min.js`，无构建工具 |
| 数据生成 | **Python + Pillow** | 投影、轮廓解析、屋顶取色、底图切片、base64 内联 |
| 数据格式 | **`CAMPUS_DATA`（JSON）** | 建筑/路/水/林/场/传送点，全部以"米"为单位 |
| 底图 | **Esri World Imagery** 卫星瓦片 | 拼接成 `mosaic_full.png`，再切成 4×4 内联 JPEG |
| 矢量来源 | **OpenStreetMap**（Overpass 导出 `osm.json`）| 楼/路/湖/树/操场的真实轮廓 |
| QA | **Playwright + 无头 Chrome**（`playwright-core`）| 脚本化机位截图，回归验收 |
| 测试 | **Node.js `node --test`** | 地面稳定性、招牌、按键等回归用例 |
| 高清替身 | **Blender → GLB 英雄模型** | `hero-*` 模块：主楼可叠高精度模型，平时用盒子兜底 |
| 编码环境 | **Codex（经 cc-switch 本地中转）** | 你的 vibe coding 主战场；换 Clash 节点对它无效（走 127.0.0.1 本地代理）|

### 3.2 数据→米 的投影公式（`gen.py`）

```python
Z = 19                       # 瓦片缩放级别
S = 156543.03392 * cos(lat0) / 2**Z   # 米/像素
# 经纬度 → Web Mercator 瓦片坐标 → 米（原点 = 校园中心 LAT0,LON0）
def m(lat, lon): ...
```

核心思想：**Web 墨卡托投影 + 固定缩放级别**，把经纬度变成和卫星图像素 1:1 对应的米，于是 OSM 轮廓能"贴"在卫星底图上。

### 3.3 建筑渲染分流（`campus.js → makeBuilding`）

```
building
 ├─ kind === 'dormitory'        → style='dorm'   : 坡屋顶(frustum) + 两端红砖楼梯间 + 米黄墙
 ├─ kind === 'university'       → style='uni'    : 坡屋顶 + 立柱立面(grandBuildingFacade)
 ├─ 主教学楼(特判)              → 'main-landmark': 山花+柱廊+暖色玻璃+广场灯
 ├─ h<5 / service / gate       → 素色 Lambert 盒子
 └─ 其它                        → plain
```

高度来自 `b.h`；`h>6` 自动加勒脚基座；`h>9 且面积>500` 自动在屋顶撒设备机房；`name` 非空自动生成楼顶招牌（`labelSprite`）。

### 3.4 地面与碰撞

- 地面 = 4×4 卫星瓦片拼成的 `MeshBasicMaterial` 平面（`campus.js` 内 `SAT_TILES`）。
- 碰撞 = 建筑多边形（圆形角色 + 线段最近点）+ 圆形障碍网格（`GRID=24`），保证第一人称不会穿墙、不会掉进湖里。

### 3.5 漫游与交互（`game.js`）

- 第一人称 WASD + 鼠标视角；`F` 飞行模式；`N` 昼夜；`M` 小地图；`T/G` 视角复位/高空。
- `Digit1~6` 一键传送到 `places` 列表里 6 个标点（南门/广场/宿舍区/田径场/公园/东侧空地）。

## 四、你（vibe coding）复刻这套的完整步骤清单

1. **取数据**：Overpass 取校园 OSM（导出 `osm.json`）；下载 Esri 卫星瓦片拼成 `mosaic_full.png`。
2. **跑 `gen.py`**：生成 `data.json` / `data.js`（建筑+道路+屋顶色）和 `tiles.js`（内联底图）。
3. **开 `index.html`** 看效果：默认会把所有楼拉成盒子 + 贴卫星地面。
4. **调风格**：改 `visual-style.js` 的预设（墙色/屋顶/是否带柱廊）；改 `campus.js` 的 `makeBuilding` 分流规则。
5. **补真实感**：把主楼做成地标立面；有精力再 Blender 建 GLB 走 `hero-*` 叠加。
6. **加交互细节**：路名、招牌、传送点、昼夜光。
7. **写验收**：`tools/render-*.mjs` 用 Playwright 飞机位截图；`tests/*.test.js` 守住回归。
8. **迭代**：把截图甩给 AI（Codex），说"这块空地是 XX，照旁边那栋做"，AI 改 `data.js` / `campus.js`，你截图验收——循环。

> ⚠️ 关键陷阱：`gen.py` 是**数据真理源**。所有"手动加的楼/路"要写进 `gen.py` 的 `MAN` 表或对应解析分支，否则下次跑 `gen.py` 会覆盖你直接改的 `data.js`。本次加的 4 栋研究生宿舍目前只在 `data.js` 里，还没回流到 `gen.py`。
